# Решения и ограничения

## Решения

| # | Решение | Почему |
| --- | --- | --- |
| 1 | Монорепозиторий, один Go-модуль `sam`, каждый сервис в `services/<name>` со своими `cmd`, `internal`, `migrations`, `Dockerfile` | Общие пакеты в `pkg/` без версионирования, независимая сборка образов |
| 2 | API Gateway — nginx, а не отдельный сервис | Маршрутизация, лимиты и CORS не требуют кода; сервисы сами публикуют REST и сами проверяют JWT |
| 3 | Аутентификация вынесена во внешний IdP; в стеке только проверка RS256 | По ТЗ IdP внешний. `tools/devtoken` подписывает токены для трёх демо-пользователей |
| 4 | Межсервисные токены HS256 с отдельным issuer и сервисными ролями | Простая ротация одним секретом, сервисные роли нельзя получить пользовательским токеном |
| 5 | Пользовательский токен пробрасывается по цепочке chat → llm → license | RBAC инструментов ассистента обеспечивает license, а не промпт |
| 6 | gRPC для синхронных межсервисных вызовов, NATS JetStream для инвентаря | Импорт крупного CSV не блокирует запрос, повторы и backpressure обеспечивает брокер |
| 7 | Поток `INVENTORY` с WorkQueue retention, `Nats-Msg-Id = snapshot_id` | Сообщение удаляется после Ack, дубликаты публикации отбрасываются окном дедупликации |
| 8 | Захват снимка через lease + `attempt_token` | Повторная доставка после `AckWait` не перезапишет результат параллельной попытки |
| 9 | Идемпотентность синхронизации через `processed_snapshots` и сравнение `collected_at` | Повтор импорта и доставка старого снимка не меняют текущее состояние устройства |
| 10 | `source_key` = sha256 от нормализованных полей с префиксами длины | Стабильный ключ кэша и alias, без коллизий при конкатенации |
| 11 | Каскад сопоставления: alias → точное совпадение → pg_trgm кандидаты → LLM → ручная проверка | Дешёвые детерминированные шаги покрывают большинство строк, LLM выбирает только из кандидатов |
| 12 | Ответ LLM при сопоставлении валидируется: id должен быть среди кандидатов, уверенность выше `MATCH_LLM_ACCEPT_CONFIDENCE` (0.85) | Модель не может придумать продукт |
| 13 | Комплаенс детерминированный, находки с `finding_key` и upsert/resolve | Повторяемый результат, история статусов, без дублей |
| 14 | Advisory-лок на продукт при пересчёте | Параллельные синхронизации разных ПК не дают гонок в балансе лицензий |
| 15 | Каждый сервис мигрирует свою БД при старте (goose, embed, session-лок) | Нет отдельного шага миграций, безопасно при нескольких репликах |
| 16 | Отдельные БД и пользователи для inventory/license/chat в одном PostgreSQL | Изоляция данных сервисов без накладных расходов нескольких кластеров |
| 17 | Провайдер LLM выбирается через `LLM_PROVIDER`; по умолчанию `mock` | Стек поднимается без ключей; GigaChat и OpenAI-compatible подключаются конфигурацией |
| 18 | Промпты встроены через `embed` и версионируются (`matching-v1`, `eula-v1`) | Анализ EULA кэшируется по хэшу текста и версии промпта |
| 19 | Результат анализа EULA требует подтверждения администратором | ТЗ: AI только предлагает, решения о лицензировании принимает человек |
| 20 | Distroless nonroot образы, healthcheck подкомандой бинарника | Минимальная поверхность атаки, нет shell в контейнере |
| 21 | Пагинация `page`/`limit` (по умолчанию 50, максимум 200), единый формат ошибок `{error:{code,message,request_id}}` | Предсказуемый контракт для фронтенда |

## Известные ограничения

- **Нет transactional outbox.** Между записью снимка в `inventory_db` и публикацией в NATS есть окно: при падении
  processor событие не уйдёт. Компенсируется авто-возобновлением незавершённых импортов при старте и
  `POST /imports/{id}/retry`.
- **Группировка CSV в памяти.** Строки группируются по устройству в map; файл 50 МБ укладывается в память, но для
  файлов на порядок больше нужна внешняя сортировка или потоковая группировка.
- **Бюджет токенов LLM хранится в памяти** сервиса llm и сбрасывается при рестарте; при нескольких репликах лимит
  считается на каждую отдельно.
- **Mock-провайдер не стримит по-настоящему**: готовый ответ режется на куски. GigaChat и OpenAI-compatible
  стримят через SSE провайдера.
- **Нет высокой доступности**: по одному экземпляру PostgreSQL, NATS и сервисов, без репликации.
- **Метрика `CONCURRENT` не проверяется** — по данным установок нельзя узнать одновременное использование, такие
  балансы помечаются `UNSUPPORTED_METRIC` / `LICENSE_UNVERIFIED`.
- **Alias в демо-данных не заведены** — они появляются при ручном подтверждении сопоставлений и после ответа LLM.
- **Слабые кандидаты для части продуктов.** Например, для `Microsoft Visual Studio 2022` pg_trgm находит одного
  кандидата из-за похожести редакций, и без LLM такая строка уходит на ручную проверку.
- **Кэш сопоставлений worker локальный** (LRU с TTL); после изменения alias в license старое значение живёт до
  истечения TTL.
- **Агент не аутентифицируется отдельно**: роль `INVENTORY_AGENT` предусмотрена, но токены выдаёт тот же внешний IdP.
- **Нет метрик Prometheus и трассировки**, только структурированные логи с `request_id`.
- **Тесты не входят в поставку** по требованию; проверка выполнена сквозным сценарием `make smoke` и ручными
  проверками, перечисленными в TASKS.md.
