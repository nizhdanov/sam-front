# Статус по User Stories v2

Проверено сценарием по всем историям на локальном стеке (mock LLM). На сервере с GigaChat — после выкатки.

| US | Что реализовано | API |
| --- | --- | --- |
| US-01 | Роли ADMIN и USER, проверка в каждом сервисе; USER привязан к компьютеру claim `device_serial` | все |
| US-02 | Единый каталог: раздел/класс, тип лицензии, бесплатно/платно, признак БПО, статус Актуальное/Устаревшее/Запрещённое, куплено мест; фильтры и поиск | `GET /software` |
| US-03 | Карточка продукта, создание/изменение; запрет требует комментария; удаление блокируется при установках или договорах | `POST/PATCH/DELETE /software/{id}` |
| US-04 | Справочник соглашений: тип, модель оплаты, текст или файл (.txt/.pdf/.docx), счётчик продуктов, запрет удаления используемого | `/agreements`, `/agreements/{id}/file` |
| US-07 | Реестр устройств: тип (VM определяется по серийнику), статус «Новое из выгрузки», ручные поля, история импортов | `/devices/{id}`, `/data/devices` |
| US-08 | Предпросмотр 20 строк до подтверждения, отчёт загружено/дублей/исключено/ошибок, дедупликация «устройство + имя + версия», KB-обновления не учитываются, нераспознанное — в очередь | `/imports`, `/imports/{id}/confirm` |
| US-09 | Реестр установок по устройству и по продукту, фильтр «распознано / не распознано» | `/data/installations` |
| US-10 | KPI: устройства, установки, % распознанного, дефицит, простаивающие лицензии, запрещённое, устаревшее, истекающие договоры | `/dashboard` |
| US-11 | Куплено vs установлено с дефицитом и свободным остатком; вид «БПО — бесплатное»; раскрытие в устройства | `/balance`, `/data/installations?product_id=` |
| US-12 | Запрещённое и устаревшее ПО (версия ниже актуальной), «обработано» с комментарием, экспорт | `/data/findings`, `/compliance/findings/{id}/acknowledge` |
| US-13 | Экспорт любых таблиц в CSV/XLSX | `?format=csv|xlsx`, `POST /export` |
| US-14 | Очередь нераспознанных с предложением и confidence, принять/отклонить/выбрать другой, пересчёт без импорта | `/matching/pending` |
| US-15 | Правила «сырое имя → продукт», редактирование и удаление, настраиваемые пороги | `/matching/rules`, `/matching/settings` |
| US-16 | AI-разбор с тип/коммерция/подписки/автопродление/ограничения/риски и ссылками на абзацы, «Сохранить в лицензию» | `/agreements/{id}/analyze`, `/analysis/approve` |
| US-17 | Топ-3 похожих соглашений | `/agreements/{id}/similar` |
| US-18 | Чат: вывод + таблица Markdown, ссылки на устройства/продукты/договоры, типовые вопросы, учёт роли | `/chat/...`, `/chat/suggestions` |
| US-19 | История диалогов, выгрузка таблиц ответа в XLSX | `/chat/conversations`, `POST /export` |
| US-20 | Журнал изменений с фильтрами по пользователю, объекту, периоду | `/audit` |
| US-21 | Чат для USER только по бесплатному/запрещённому ПО и своему компьютеру | `/chat/...` |
| US-22 | Экран USER: свой компьютер, запрещённое и устаревшее ПО на нём | `/me/device`, `/data/findings`, `/data/installations` |

## Ограничения

- Журнал изменений ведётся в license; импорты отражены в истории импортов processor (`GET /imports`), а не в `/audit`.
- Сходство соглашений (US-17) считается по тексту триграммами, без семантических эмбеддингов.
- PDF без текстового слоя (скан) не распознаётся.
- Качество ответов чата и разбора EULA зависит от модели; на mock-провайдере ответы демонстрационные.
